## 0. 결론 먼저 (P1 직언)

**가장 큰 리스크 — 시기.** 오늘은 공인중개사 D-59다. OS §8 리스크 1번("시스템 공사가 공부를 대체")은 네가 스스로 적은 최대 리스크인데, 8/26 "엔진 동결" 선언 이후 9/1 하루에만 README 기준 개정 9건이 들어갔다. 지금 통합 공사(템플릿 6벌→1벌, 원장 3벌→1벌, 검증 6벌→1벌)를 시작하면 시험 전 2~3일이 엔진에 들어가고, 실패 시 아침 루틴이 끊긴다. **본공사는 10/31 이후로 미루고, 지금은 "안전 수리 4건 + 결정 확정"만 한다.**

**반대 관점.** "이미 잘 돌고 있다(56회 제출·평균 33/36, 오답 루프 회귀 정상) — 손대지 말라." 절반은 맞다. 코드 품질은 좋고 원장 설계는 상위권이다. 그러나 실측이 말하는 진짜 문제는 코드가 아니라 **학습 커버리지**다: 오래된 노트 198개 중 153개(77%)가 시험 59일 전인 지금까지 한 번도 장기복습에 돌아오지 않았고, 졸업 직전 개념 15개 중 10개는 큐 맨 뒤에 갇혀 최장 44일째 안 나온다. "배운 것은 반드시 돌아온다"는 모토가 데이터에선 아직 거짓이다. 이건 공사가 아니라 **파라미터 2개 조정**으로 지금 고쳐야 한다.

**판정.**
| 단계 | 시기 | 내용 | 시간 상한 |
|---|---|---|---|
| Phase 0 | 지금 ~ 10/31 | 안전 수리 4건(학습 효과 직결) + 죽은 파일 정리 + 결정 확정 | **총 3시간** |
| Phase 1 | 11/1 ~ 11/7 | 통합 공사(코드·템플릿·검증·문서 단일화) — 법무사 평일 전환 작업과 같은 주 | 2블록(주말 롱블록 1 + 저녁 2회) |
| Phase 2 | 11월 중 | 지표 관찰 → 유지/폐기 판정(표식 파이프라인 등) | 주 30분 |

## 3. 목표 구조 (To-Be, Phase 1)

### 3-1. 원칙 — "AI는 창작만, 기계적인 것은 전부 스크립트"

지금은 AI가 ① 원천 선정 ② 한달전 복원 복사 ③ 장기복습 버킷 선정 ④ 정답 위치 배정 ⑤ 문항 작성 ⑥ HTML 토큰 치환 ⑦ 검증 ⑧ 로그 갱신 ⑨ 푸시 페이로드를 전부 한다. 이 중 **AI가 해야 하는 건 ⑤뿐**이다. 나머지를 스크립트로 옮기면 규칙 문서가 절반 이하로 줄고, 9/1류 사고(정답 배정 어긋남)는 발생 자체가 불가능해진다.

```
prepare_quiz.py --exam gongin --kind daily
   → plan.json : 모드(고정/램프업/전일)·쿼터·읽을 노트 목록·장기복습 선정·한달전 블록(원문 복사)·과거 문제문 색인
AI : plan.json + 노트 정독 → questions.json (신규 문항만. 객관식은 correct 텍스트 + distractors, 위치 미지정)
render_quiz.py questions.json
   → 정답 위치 배정(분산·3연속 규칙) · 조합형 지문 순서 셔플(ㄱ 편향 기계적 제거) · 한달전 블록 병합
   → 단일 템플릿 렌더 → validate → _장기복습_로그·_push 갱신 → 실행 로그 1줄
```
