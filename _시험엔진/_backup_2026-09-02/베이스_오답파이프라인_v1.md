## 0. 경로 (마운트 지연 대비 — 반드시 재시도)
- ⚠️ 워크스페이스 마운트는 늦게 붙는다. 첫 조회가 비어도 '부재'로 단정하지 말 것 (2026-07-27 사고 교훈).
```bash
for i in 1 2 3 4 5; do
  ROOT=$(find /sessions/*/mnt -maxdepth 2 -type d -name velog-posts 2>/dev/null | head -1)
  [ -n "$ROOT" ] && break
  echo "velog-posts 마운트 대기... ($i/5)"; sleep 5
done
DL=$(ls -d /sessions/*/mnt/Downloads 2>/dev/null | head -1)
BASE=$ROOT/⟨프로파일: EXAM_DIR⟩/claude_ox_오답; RQ=$ROOT/⟨프로파일: EXAM_DIR⟩/오답퀴즈
```
- 5회 후에도 ROOT가 비면 파일 도구로 `~/Desktop/velog-posts` 직접 확인, 그래도 실패 시 "velog-posts 접근 불가 — 전 단계 중단"을 보고하고 종료(엉뚱한 곳에 생성 금지).
- 밀린 과거 날짜분을 만들지 않는다 — 항상 오늘 하루치만.

## 1. 수거 (Downloads → `$BASE/_inbox/`)
- 패턴은 반드시 `⟨프로파일: RESULT_GLOB⟩`를 그대로 쓴다 (과목명이 낀 변형 `공인중개사_민법전범위_오답_*.json`을 놓친 실사고 교훈 — `*오답_*`가 핵심):
```bash
cp -n "$DL"/⟨프로파일: RESULT_GLOB⟩ "$BASE/_inbox/" 2>/dev/null
```
- 다른 시험 파일은 건드리지 않는다(그 시험의 파이프라인 소관).
- 브라우저 사본 `... (1).json`도 그대로 복사한다(원장이 사본을 제거한다). 오답 재도전 퀴즈의 결과(`*-RQ.json`)도 같은 패턴에 자동 포함된다 — 이게 졸업·재도전 판정의 원천이다.
- **Downloads는 읽기 전용** — 삭제·이동·수정 금지, `cp -n`만.
- Downloads 미마운트여도 종료하지 않는다 — "Downloads 미연결: 기존 _inbox 분만으로 진행"을 보고에 명시하고 계속한다.

## 2. 원장 갱신 (이 시험의 원장만)
```bash
cd "$BASE" && python3 _ledger/build_ledger.py --ingest
```
- `⟨프로파일: 대시보드⟩`가 정의된 시험이면 원장 갱신 성공 후 이어서 실행한다. 정의가 없으면 생략(정상 — 이식 안 한 시험).
- exit 2(원천 0건)는 원장 초기엔 정상일 수 있다 — 출력 그대로 보고하고 §3을 건너뛴다. 다른 오류도 숨기지 말 것.
- 갱신된 `$BASE/_ledger/오답_원장.json`을 읽는다. **이후 모든 수치·듀큐는 이 파일에서만 가져온다.** 다른 시험의 원장 교차 사용 금지(남의 원장으로 이 시험 퀴즈를 만들면 안 된다).

## 3. 오답 재도전 퀴즈 생성
### 3-1. 편성 판정 (기계적)
- `N = min(⟨프로파일: 오답 상한⟩, dueQueue 길이)` (슬롯 미정의 시 20). **N = 0이면 오늘은 미생성** — "듀 0 — 오답퀴즈 없음" 한 줄 보고. 듀보다 많이 내려고 다른 원천을 끌어오지 않는다(FSRS 마감 도래분만이 원천이다).
- `$RQ/{오늘날짜}.html`이 이미 있으면 오늘 퀴즈는 생략(수거·원장은 이미 수행됨). 덮어쓰기 금지.
- 출제 대상 = dueQueue **상위 N개** (원장이 이미 상습 우선 → 망각위험 오름차순으로 정렬해 둠 — 재정렬 금지).
### 3-2. 문항 작성 (전 문항 재도전 표기)
- 근거 = 각 듀 항목의 원장 `samples`(원 문제·해설)와 이 시험의 학습 노트(`⟨프로파일: 신규 원천 규칙⟩`이 가리키는 폴더 — 트랙 분할 시험은 공유 노트 폴더). **여기 없는 내용 창작 금지.** 근거가 정말 부족한 개념은 건너뛰고 다음 듀 항목으로 대체하되 보고에 명시.
- **변형 출제**: 원 문제 복사 금지 — 같은 개념을 다른 각도·다른 숫자(긍정↔부정, 정의↔사례, 주체·기간 교체, 방향 뒤집기)로. 오답 보기는 정답과 '한 끗 차이', 더미 금지.
- **조합형 위치-참거짓 무상관 (v1.6)**: ㄱㄴㄷ 조합형에서 지문의 위치와 참·거짓은 무관해야 한다 — **ㄱ이 거짓인 문항을 의도적으로 섞는다**(세트 기준 ㄱ·ㄴ 각각의 정답 조합 포함 비율 25~75%, §3-4에서 조합형 ≥4문일 때 기계 검사). 근거 실측(2026-09-01): 기존 조합형 325문에서 ㄱ 포함 95%·ㄴ 83% — '앞 지문은 참' 메타 단서가 성립해 지문을 읽지 않고도 선지가 소거된다.
- **단답 승격 (v1.3, 2026-09-01) — 객관식 트랙 전용.** 출제 대상 N개를 고른 뒤, 그중 **반복 실패 개념**은 객관식이 아니라 **단답형으로 승격**해 출제한다.
  - **승격 조건 (듀 항목 필드로 기계 판정)**: `status === "상습"` ∨ `retryMissed ≥ 1` ∨ `timesWrong ≥ 3`. 셋 중 하나면 승격.
  - **상한**: `⟨프로파일: 단답 승격 상한⟩` (미정의 시 **0** = 승격 없음 / 전 문항 단답 트랙은 해당 없음). 조건 충족이 상한을 넘으면 **듀 큐 정렬 순서 상위부터** 승격하고 나머지는 객관식 유지.
  - **필드 계약**: 그 트랙 데일리의 단답 계약과 동일(`answer` 모범답 문자열 + `keywords` 2~4 + `opts` 없음, 발문 쓰시오체). 재도전 표기 3종(🔁·conceptKey·retryOf)은 그대로.
  - **missedTop과의 결합**: 승격 문항에 missedTop이 있으면 위 조준 규칙의 단답 트랙 방식(발문을 그 요소로 좁히고 keywords 맨 앞)을 그대로 쓴다.
  - **왜**: 객관식 재도전은 보기가 답을 반쯤 들고 있는 **재인지** 과제다. 같은 개념을 3번 틀렸다는 건 재인지 수준의 복습으로는 안 뚫린다는 뜻 — 인출 강도를 한 단계 올린다(데일리 단답 치환과 같은 근거). 승격 문항 수와 대상은 보고에 명시한다.
  - 시험 임박 실전형식 보호(D-14 승격 0 등)는 프로파일이 정한다.
- **놓친 포인트 조준 (v1.2, 2026-09-01) — 변형 각도보다 우선한다.** 듀 항목에 `missedTop`(원장 `ledger[].missedKeys` 빈도순 상위 3, md 듀 표의 `놓친 포인트` 열)이 있으면, 그 포인트를 **정면으로 겨냥해** 출제한다. 이건 AI의 추정이 아니라 **본인이 자가채점에서 "이것 때문에 틀렸다"고 직접 고른 것**이라 가장 신뢰도 높은 조준 정보다.
  - **단답 트랙**: 발문을 그 요소로 좁힌다(예: `missedTop=["현재의 위난"]` → "긴급피난의 위난 요건이 갖춰야 할 성질을 쓰라"). `keywords`에 그 포인트를 **반드시 포함**하고 **맨 앞**에 둔다.
  - **객관식 트랙**: 그 포인트가 **정답을 가르는 축**이 되게 지문을 짠다 — 오답 보기는 바로 그 요소를 빼거나 바꿔 만든다.
  - **`결론·방향 자체`가 들어 있으면** 요소 암기가 아니라 결론이 무너진 것이다 → 사례를 주고 **결론과 근거를 직접 묻는** 형태로(2차는 미니답안형 우선).
  - **`기타: …`로 시작하면** 채점 포인트에 없던 원인을 본인이 직접 적은 것이다(v1.4). 콜론 뒤 문장이 **가장 구체적인 조준 정보**니 그대로 겨냥하되, 표현은 본인 메모가 아니라 **학습 노트·원장 samples의 용어로 번역해서** 발문·keywords에 넣는다(메모 문구를 그대로 keywords에 박지 않는다 — 채점 앵커는 노트 표현이어야 한다). 메모가 모호해 무엇을 겨냥할지 정할 수 없으면 **조준을 포기하고 종전 변형 각도로** 낸다(추측해서 엉뚱한 데를 파지 않는다).
  - `missedTop`이 여러 개면 **1문항에 1포인트**만 조준한다(여러 개를 한 문항에 몰면 뭘 때문에 또 틀렸는지 다시 안 보인다). 나머지는 다음 듀 회차로.
  - `missedTop`이 비어 있으면(`—`) 종전대로 개념 전체를 변형 출제한다. **없다고 지어내지 않는다.**
- **원인 라우팅 (v1.5, 2026-09-01) — 객관식 오답의 자기진단을 재출제 각도에 반영한다.** 듀 항목의 `causeTop`(원장 `ledger[].errorCauses` 최빈 원인 — 채점 후 본인이 고른 개념부재/혼동/함정/실수, md 듀 표의 `원인` 열)이 있으면:
  | causeTop | 재출제 각도 |
  |---|---|
  | **개념부재** | 정의·요건을 **정면으로** — 단답 승격 대상이면 용어정의·요건개수형 발문 |
  | **혼동** | **비교·판별식 각도** — 오답 보기(또는 단답 발문의 대비 항)에 혼동 상대를 정면 배치. samples의 `causeNote`에 상대가 적혀 있으면 그것이 1순위 재료 |
  | **함정** | **같은 함정 유형의 변형 지문** — 트랙 함정 패턴표 참조(다른 소재·같은 구조) |
  | **실수** | **각도 변경 없음** — 개념 설명을 보강하지 않는다(실수를 개념 문제로 위장 금지 — 72초 룰). FSRS 스케줄대로 재출제만 |
  `causeNote`는 '기타' 메모와 동일 규칙 — 표현은 노트·samples 용어로 번역하고, 모호하면 무시. missedTop 조준과 겹치면 **missedTop(무엇을 놓쳤나)이 소재, causeTop(왜 틀렸나)이 각도**다 — 충돌 개념이 아니라 직교한다. causeTop이 없으면(과거 데이터) 종전 변형 각도.
- **배제(v1.1)**: 노트의 ⚠️·'확인 필요' 항목(검출 키: 정규식 `⚠️?|확인 ?필요`)은 변형 출제 원천에서 제외한다.
- **정답-해설 정합 (v1.7, 2026-09-01 실사고)**: 정답 사전 배정(분산 맞추기) 때문에 **내용상 정답 보기와 `answer` 인덱스가 어긋나는 사고**가 실제 발생했다(부정형 발문에서 answer가 참 지문을 가리키고 해설은 다른 보기를 설명 — 당일 데일리 1번). 문항마다 해설을 쓴 직후 `opts[answer]`를 다시 읽고 **"[정답 근거]가 설명하는 보기가 바로 이 보기인가"를 자문**한다. 검증 스크립트의 정합 휴리스틱(해설 첫 문장↔보기 2-gram 대조)에 걸리면: answer 오배정이면 answer를 고치고, 오탐이면 [정답 근거] 첫 문장을 정답 보기를 직접 서술하도록 다시 쓴다 — 어느 쪽이든 결과물이 좋아진다.
- 표기 3종 전 문항 필수: 문제문 맨 앞 `🔁 `, `conceptKey` = 듀 항목 값 **그대로 복사**(원장 매칭 키 — 변형 금지), `retryOf` = 같은 값. `src` = samples의 원 출처(없으면 "오답원장") + 끝에 `(재도전)`.
- 필드 계약: `{type, cat, q, opts, answer, expl, src, conceptKey, retryOf}`. 해설은 `[정답 근거]→[메커니즘 1문장]→[함정 1문장]` 3문장 250자 이내. 문자열에 큰따옴표(")·백틱 금지(따옴표는 ').
- **문항 형식**: `⟨프로파일: 문항 형식⟩` — 유형 구성·단답/객관식 판정·금지 유형·정답 균형 규칙은 프로파일이 정한다.
### 3-3. HTML 생성
- 템플릿 = `$RQ/_template.html` (데일리퀴즈 정본의 사본 — **JS·CSS 수정 절대 금지**, 데일리퀴즈 정본 원본도 건드리지 않는다).
- 토큰 교체만: `{{QUIZ_DATE}}` → 오늘날짜(두 곳) / `{{META_LINE}}` → "2026년 M월 D일 (요일) · 오답 재도전 N문항 · 듀 잔여 M개" (M = dueQueue 길이 − N) / `{{TAGS_HTML}}` → `<span class="tag">🔁 오답 재도전 N</span>` + 오늘 과목명 태그들 / 템플릿에 `{{ALERT_HTML}}`가 있으면 → 빈 문자열 / QUESTIONS 마커 사이에 배열 삽입.
