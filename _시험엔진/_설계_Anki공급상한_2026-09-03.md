**리스크(P1):** 신규 = 미래 리뷰 예약. 주 140장을 9월 4주 유지하면 10월 중순 일일 리뷰 120~160장(20~25분)에 도달 — 파이널(국면 2)과 겹친다. 따라서 ① 신규/일 30으로 즉시 올리지 않고 20을 꽉 채우는 데서 시작 ② 2주 관찰 게이트 후 승격 ③ 국면 2 규칙(10/1 신규 5·D-14 신규 0)은 공급 측에도 연동한다.

**반대 관점:** 남는 시간을 파지율(0.90→0.93)에 써서 기존 카드 회상률을 올리는 방법도 있다. 요청이 커버리지("놓치지 않기")라 공급 확대를 1순위로, 파지율은 Phase 2 선택지로 둔다.

### 2-2. `engine/build_apkg.py` — 소프트 상한 경고 (순수 추가·차단 없음)

- **모델 ID 상수·guid·deck id 로직·검증 로직은 한 글자도 바꾸지 않는다.**
- `main()`의 "빌드 결과 검증" 블록에서 `card_count` 산출 직후, 다음을 추가:
  1. 정규 덱 여부 판정: `date_str`이 `^\d{4}-\d{2}-\d{2}$`와 정확히 일치할 때만(특집 접미사 있으면 건너뜀).
  2. `exams.json` 로드: 빌더 파일 위치 기준 `os.path.join(os.path.dirname(os.path.abspath(__file__)), "exams.json")`. 없거나 `_anki.weekly.card_ceiling`이 없으면 조용히 건너뜀(try/except — 빌더는 exams.json 없이도 동작해야 한다).
  3. `card_count > ceiling`이면 출력: `[경고] 총 카드 {card_count}장 > 주간 소프트 상한 {ceiling}장 — 신규 {new_per_day}/일 기준 {card_count/new_per_day:.1f}일치. 8일치 초과면 다음 주 lane_cap 하향 (exams.json _anki)`. 그 외에는 `  주간 상한 : {card_count}/{ceiling}장 (신규 {new_per_day}/일 기준 {일치}일치)` 1줄 정보 출력.
  4. 반환값·exit code 불변(경고는 0).
- 파일 상단 docstring "출력" 절 아래에 2줄로 이 동작을 기술한다.

### 2-4. `spec/앙키덱.md` — 절차 갱신 (≤80줄 유지)

1. 머리 **실행 원칙 ④** 문구: "주 25장 상한 안에서 경쟁(자를 때 우선순위 상습 오답 > 백지 구멍 > ★, 잘린 ★는 이월)" → "경쟁 레인 상한(**정본 `engine/exams.json` `_anki.weekly.lane_cap_notes` — 현재 60노트**) 안에서 경쟁. 절단 우선순위 상습 > 백지 구멍 > ★ > n:, 같은 레인 안에서는 이월 → 시험일 가까운 순 → 노트 날짜 순. 잘린 항목은 검수리포트 이월 표에 남겨 다음 주 최상단". 원칙 ⑦ 추가: "**정규 덱 총 카드가 `_anki.weekly.independent_review_min_cards`(30) 초과면 별도 에이전트 전수 원문 대조 필수** — 결과(사실 오류 N·인출 설계 결함 N)를 검수리포트 머리에 기재".
2. **§0**에 1줄: "`exams.json` `_anki`를 먼저 읽어 `lane_cap_notes`·`card_ceiling`·`final_phase`를 확정한다. 오늘이 `final_phase.gongin.from` 이후면 공인중개사 레인은 그 값으로, `exam_date − stop_from_days_before_exam` 이후면 공인중개사 카드 출고 0(법무사만)."
3. **§1 표**: ②-B 행 "상한 25 안에서 경쟁" → "레인 상한 안에서 경쟁(`_anki`)". 행 추가 **④ 이월**: `$AK/출고/검수_<직전 정규 덱 날짜>.md`의 「## 이월 (다음 주 우선)」 표 — 원문(원장·노트·백지 보고서)을 **다시 대조**한 뒤 편입, 원문이 사라졌으면 탈락 기재. 같은 항목이 2주 연속 이월이면 상습 앞으로. 행 추가 **⑤ `n:`**: §6-1에서 수집한 줄머리 `n:` 라인 중 출고 key에 없는 것 — 최저 우선순위, `⚠️`/확인 필요 동반 시 제외(②와 동일 앵커 규칙).
4. **§1 끝**에 절단 절차 1문단: 후보 총계 → ★★ 전량 확정 → 나머지를 `lane_priority` + tiebreak로 정렬해 `lane_cap_notes`까지 채움 → 나머지는 이월 표로. 빌드 후 총 카드가 `card_ceiling` 초과면 자르지 말고 검수리포트 머리에 "신규 N/일 기준 X일치" + "다음 주 lane_cap 권고값" 표기.
5. **§4 검수리포트**: 상한 집계 문구 "(상습+백지+★ ≤ 25, ★★ 제외)" → "(경쟁 레인 ≤ `lane_cap_notes`, ★★ 제외) + 총 카드/`card_ceiling` + 소화 일수 + 독립 검증 결과". 꼬리의 "상한 초과 이월 목록" 섹션 제목을 **정확히 `## 이월 (다음 주 우선)`**으로 고정하고 열을 `원천 | 레인 | 항목 | 이월 횟수 | 사유`로 고정(다음 주 §1-④가 기계적으로 읽는다).
6. **§5 전달** 고정 안내에 "이번 덱 N장 = 신규 20/일 기준 X일치" 추가.
7. **§6-4**: "`n:`의 Anki 편입은 자동 아님(`!` 병기분만)" → "`n:`은 §1-⑤로 경쟁 레인 최저 순위에 자동 편입(2026-09-03) — §6은 정본 통합만 담당".
