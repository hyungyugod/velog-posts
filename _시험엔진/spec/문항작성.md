# 문항 작성 규칙 + questions.json 계약 (전 시험 공통)

> 실행자(AI)가 문제지 생성에서 하는 일은 **이것 하나** — `questions.json`을 쓰는 것. 원천 선정·정답 위치·렌더·검증·로그는 전부 `engine/` 스크립트가 한다.
> 시험별 수치(문항 수·유형 쿼터·보기 수·상한)는 `engine/exams.json`이 정본이고 plan.json에 이미 계산돼 들어온다. 이 문서는 **어떻게 쓰는가**만 다룬다.

## 0. 절대 규칙 (사고에서 나온 것 — 완화 금지)

1. **노트에 없는 내용 출제 금지.** 환각 문항이 한 번 각인되면 되돌릴 수 없다. 소재가 모자라면 문항을 줄이고 사유를 보고한다(검증이 FAIL이면 그대로 보고 — 억지로 채우지 않는다). 단답은 §1-4 `evidence`(노트 원문 인용)로 이걸 **기계 검사**한다 — 인용을 못 붙이면 그 문항을 만들 근거가 없다는 뜻이다.
2. **⚠️·"확인 필요" 항목 출제 금지** (노트 하단 섹션·표·줄 — 검출 키 `⚠️?|확인 ?필요`). ★이 붙어 있어도 확인 필요가 우선.
3. **원천 노트는 처음부터 끝까지 정독**한다. 발췌·건너뛰기 금지.
4. 과거 문항(plan의 `past_questions`)과 **같은 개념·같은 각도** 반복 금지 — 다른 조문·다른 숫자·긍정↔부정·정의↔사례·방향 뒤집기.
5. 문자열에 큰따옴표(`"`)·백틱 금지(따옴표는 `'`). 발문 줄바꿈은 `<br>`만.

## 1. questions.json — 파일 계약

경로: `<시험폴더>/<데일리퀴즈|오답퀴즈>/_work/<date>.questions.json`

```json
{ "date": "YYYY-MM-DD", "exam": "gongin|bupsa1|bupsa2", "kind": "daily|retry",
  "questions": [ …문항 객체… ],
  "push_ox": [ {"q": "…", "a": "O|X", "exp": "…"} ]   ← gongin daily만, 정확히 3개(O 1~2개), 오늘 문항에 없는 새 OX
}
```

문항 수 = plan `quotas.new + quotas.longrev`(daily) / plan `n`(retry). **한달전 블록은 쓰지 않는다** — plan의 `monthly_block`이 확정본이고 렌더가 붙인다.

### 1-1. 공통 필드

| 필드 | 값 |
|---|---|
| `type` | 시험별 허용 유형(프로파일). 단답은 `"단답"` |
| `cat` | 과목명 — 노트 파일명의 과목 그대로(원장 별칭 정규화는 스크립트 몫) |
| `q` | 발문. 마커(⏪·🔁)는 **쓰지 않는다** — 렌더가 붙인다 |
| `expl` | `[정답 근거] … [메커니즘] … [함정] …` 3문장 250자 이내. **첫 문장은 정답 보기를 직접 서술**(해설↔정답 정합 검사가 여기서 걸린다). OX는 `O.`/`X.`로 시작 |
| `src` | `YYYY-MM-DD 과목 소제목` — 실제로 읽은 노트의 날짜·과목. 접미(장기복습·재도전)는 렌더가 붙인다 |
| `conceptKey` | `과목 소제목-요지` 짧게, 문제지 안 고유. **retry는 plan `picks[].conceptKey`를 글자 그대로** |
| `source` | `"new"` \| `"longrev"` \| `"blank"`(백지복습 보고서 원천). longrev는 `note`(plan `longrev_picks[].path` 또는 basename) 필수 |
| `exam` | 법무사만 `"1차"`/`"2차"` (중개사는 생략) |
| `sub` | 법무사 2차 단답 소유형(프로파일 7종) |
| `evidence` | `{note, quote}` — **단답 필수**(§1-4). 객관식은 선택(달면 같은 규칙으로 검사) |

### 1-4. evidence — 노트 원문 인용 (환각 게이트, 2026-09-02 신설)

```json
"evidence": { "note": "2026-09-05-2차-형법-(형법 위법성조각사유).md",
              "quote": "긴급피난은 현재의 위난을 피하기 위한 상당한 이유 있는 행위여야 한다" }
```

- **필수**: 데일리(daily) 본편의 `type:"단답"` 전부 — 신규·장기복습·백지 원천 가리지 않는다(전 시험). 한달전 블록은 plan 확정본이라 제외, 재도전(retry)은 선택이지만 달면 검사한다.
- `quote` = **그 노트에 실제로 있는 15~120자를 그대로 복사**. 요약·의역·재조합 금지. 긴 줄은 앞부분만 잘라 써도 된다.
- `note` 해석 순서: 절대경로 → plan `new_sources[].path`·`longrev_picks[].path`(retry는 `picks[].related_notes`)의 파일명 일치 → `<notes_dir>/<파일명>` → `<notes_dir>/백지복습/<파일명>`. retry에서 samples가 근거면 `"note": "samples"`(그때 quote는 plan `picks[].samples[]`의 `q`·`expl`에서 그대로).
- 대조 방식: 공백·마크다운 기호·구두점을 양쪽 다 지운 뒤 **부분 문자열 포함**. 하나라도 어긋나면 `render_quiz.py`가 문항·노트·quote 앞 40자를 찍고 렌더를 중단한다.
- 통과한 evidence는 **문제지 HTML에 실리지 않는다**(렌더가 떨군다) — 검사용 필드다.

### 1-2. 유형별 필드 — **정답 위치는 절대 지정하지 않는다**

| 유형 | 필드 | 렌더가 하는 일 |
|---|---|---|
| 객관식(일반·사례·판례·개수) | `correct`(정답 보기 문자열) + `distractors[]`(오답 보기, 개수 = 보기 수−1) | 정답 인덱스 균등 배정·같은 인덱스 3연속 회피 |
| 계산 | 위 + `calc:{expr, expected}` — expr은 산술만 | expr 검산·정답 보기에 값 존재 확인 |
| OX | `answer: "O"|"X"` | opts `["O","X"]` 변환. **같은 답 OX를 3문 연속 두지 마라**(렌더가 못 고침) |
| 조합 | `q`는 발문만(지문 나열 없이) + `items:[{text, truth:true|false}]` + `stem_target:"true"|"false"`(옳은 것/옳지 않은 것 모두 고르기) | 지문 순서 셔플·ㄱㄴㄷ 라벨·`<br>ㄱ. …` 나열·정답/근접 오답 조합 생성·**ㄱ 편향 제거**(세트 기준 ㄱ·ㄴ 정답 포함 25~75%) |
| 단답 | `answer`(모범답 문자열) + `keywords[]` 2~4개(채점 앵커, 핵심어만) | 그대로 |

- 오답 보기는 정답과 **한 끗 차이**(숫자 스왑·주체 교체·기간 교체·원칙↔예외·유사 제도 교차). 더미 금지. 정답 보기가 눈에 띄게 길지 않게(정답=최장보기 40% 이하 검사).
- 5지(법무사 1차) 조합형은 참(또는 거짓) 항목이 **정확히 3개**여야 한다(선지가 3개 조합 5쌍).
- 부정형 발문은 `<b>옳지 않은</b>` 굵게(중개사) / "가장 옳지 않은 것은?"(법무사 1차).

### 1-3. 단답 특칙

- 발문 "쓰시오/서술하시오/기재하시오/나열하시오/채우시오"체. `answer`에 `<br>` 외 태그·백틱·큰따옴표 금지(innerHTML 주입).
- 데일리 단답 치환(객관식 트랙): **신규 몫에서만**, 소재 우선순위 ①`★★` ②`★` ③백지복습 "남은 구멍". 후보 없으면 0문(억지 생성 금지·사유 보고). 상한·D-14 규칙은 plan `quotas.sa_swap_max`에 이미 반영.
- 표식은 **줄머리(불릿 뒤 포함)에 붙은 것만** 유효 — 문장 중간 ★·백지시트 장식은 무시.

## 2. 재도전(retry) 문항 규칙

- 근거 = plan `picks[].samples`(원 문제·해설·본인 오답·놓친 포인트·원인) + `related_notes`. **원 문제 복사 금지 — 같은 개념 다른 각도.**
- `promote_sa: true`인 pick은 **단답**으로(반복 실패 개념 승격 — 재인지가 아니라 인출). 나머지는 트랙 객관식.
- **놓친 포인트 조준**: `missedTop`이 있으면 그 요소를 정면으로 겨냥 — 단답이면 발문을 그 요소로 좁히고 `keywords` **맨 앞**에, 객관식이면 그 요소가 정답을 가르는 축. `결론·방향 자체`면 사례를 주고 결론과 근거를 묻는다(2차는 미니답안형). `기타: …`는 콜론 뒤 문장을 겨냥하되 표현은 노트 용어로. 1문항 1포인트. 없으면 지어내지 않는다.
- **원인 라우팅**(`causeTop`): 개념부재→정의·요건 정면 / 혼동→비교·판별식(혼동 상대를 오답 보기에, `causeNote`가 1순위 재료) / 함정→같은 함정 유형의 변형 / **실수→각도 변경 없음**(개념 문제로 위장 금지). missedTop=소재, causeTop=각도 — 직교.
- 근거가 정말 부족한 pick은 건너뛰지 말고 보고 — 문항 수는 plan `n`과 같아야 검증을 통과한다(부족하면 samples만으로라도 변형 출제하되 노트 밖 내용은 금지).

## 3. 작성 순서 (건너뛰기 금지)

1. plan 요약(`ai_brief`) → 쿼터·원천·픽 파악
2. 원천 정독(신규 노트·백지복습 보고서·장기복습 노트 전문) — ★★/★ 항목과 "남은 구멍"·"교정된 개념" 표 표시
3. **계획표** 먼저: `# | 소스 | 과목 | 출처 소제목 | conceptKey | 개념+함정 설계 | type` — 과목 균등(차이 ≤1)·유형 쿼터·부정형 비율을 여기서 맞춘다
4. 문항 작성 → 해설 직후 `correct`를 다시 읽고 "[정답 근거]가 이 보기를 서술하는가" 자문
5. `render_quiz.py` 실행 → FAIL 항목만 고쳐 재실행(검증 기준 임의 완화 금지)
